# Канон

Это читает каждый, кто пишет код в этом репозитории: человек, Claude, Codex — разницы нет.
Прочитай целиком до первой правки. Дальше — короткие правила, каждое с причиной: правило без
причины нарушают первым.

---

## 1. Дизайн-система — не рекомендация

Интерфейс собран на **shadcn/ui** (стиль `radix-nova`) и иконках **Lucide**. Это не «вдохновение»,
а источник компонентов.

**Нужен компонент — установи его:**

```bash
cd web && npx shadcn@latest add tabs
```

**Нельзя:** писать свой аналог существующего компонента, копировать из него куски, «временно»
собирать кнопку из `div` с классами. Если компонента нет в реестре — сначала посмотри, не
собирается ли нужное из уже установленных (`item`, `field`, `empty`, `bubble`).

Отступить можно ровно тогда, когда следование системе — блокер, и тогда рядом стоит комментарий
с причиной. Без комментария это просто самодеятельность, и её откатят.

**Почему:** каждая самодельная кнопка — это ещё один набор состояний, которые никто не поддержит:
фокус, disabled, тёмная тема, клавиатура, RTL. Система их уже держит.

**Состояния не изобретаем.** Активный пункт — `bg-accent text-accent-foreground`, фокус — кольцо
самого компонента, наведение — `hover:bg-accent/50`. Своя рамка, своё кольцо, своя подсветка
активного — это не полировка, а второй набор состояний рядом с системным.

**Состояние видно без легенды.** Текущий режим помечен бейджем «Текущий», а не инверсией
цвета, которую надо разгадывать, и не подписью под карточкой.

**Один шаблон, а не особый случай.** Встроенный режим настраивается той же карточкой, что
и остальные; человек в ленте нарисован тем же компонентом, что агент. Особый случай — это
ветка в коде, которую потом забудут обновить.

**Мы не улучшаем систему, а пользуемся ею.** Свой отступ, свой кегль, своя тень «чтобы было
красивее» — самый быстрый способ сломать экран на другой теме и другой ширине. Красиво здесь
значит «как в shadcn».

**`cn` в этом проекте не сливает классы.** Он из пакета `cn`, а не `tailwind-merge`:
`cn("h-9", "h-full")` оставит оба класса, и победит тот, что ниже в собранном CSS, — то есть
базовый класс компонента. Переопределять его строкой бесполезно: берём утилиту, которая
не конфликтует (`min-h-9` вместо `h-9`). По той же причине правило компонента, написанное
под `dark:`, переживёт твоё без `dark:`: перекрываешь такое — пиши обе версии.

## 2. Всё живёт на токенах

Цвет, размер, отступ, радиус, тень — только через токены темы (`web/src/index.css`) и шкалу
Tailwind.

- **Цвет:** `--background`, `--foreground`, `--muted-foreground`, `--border`, `--destructive`…
  Палитра участников — тоже токены: `--tone-<цвет>` (тон) и `--chroma-<цвет>` (насыщенность),
  а классы `.tone-face`, `.tone-name`, `.tone-bubble` считают из них конечный oklch.
  Заливка — прозрачность (`--tone-fill`), а не готовый цвет: так одна шкала работает и в тёмной
  теме, и в светлой. Текст прозрачностью не задать, его светлота переключается темой
  (`--tone-ink`, `--tone-label`, `--tone-accent`). Сами `.tone-*` объявлены вне `@layer`
  намеренно: иначе вариант компонента перебивает цвет участника.
- **Размер:** классы шкалы (`text-sm`, `size-8`, `gap-3`). Не `style={{ fontSize: 13 }}`.
- **Никаких hex в компонентах.** Появился новый цвет — он появляется в теме, а не по месту.

Единственное законное исключение — величина, которой в шкале нет (например `max-h-[85vh]`
у диалога). Тогда рядом комментарий, почему.

**Почему:** тема меняется в одном файле. Пиксель, вписанный в компонент, не меняется никогда.

## 3. DRY: одна причина — одно место

Если знание повторяется дважды, второе место — будущая рассинхронизация.

| Знание | Единственное место |
|---|---|
| Палитра и тема | `web/src/index.css` |
| Размеры аватарки | `FACE_SIZES` в `web/src/components/chat-feed.tsx` |
| Выбор цвета и знака | `web/src/components/face-picker.tsx` |
| Тексты оболочки | `web/src/lib/i18n.tsx` |
| Русская типографика | `web/src/lib/typo.ts` |
| Латиница из кириллицы | `web/src/lib/latin.ts` |
| Обращения к серверу | `web/src/lib/api.ts` |
| Состояние комнаты на диске | `lib/state.js` |
| Поведение роли | `roles/<роль>.md` |
| Устройство режима | `modes/<режим>.md` |
| Значения по умолчанию | `lib/config.js` → `DEFAULTS` |

Роли и режимы — файлы, а не код: они перечитываются на каждый ход, правка видна без перезапуска.
Новая роль или режим = новый файл, а не ветка в `if`.

## 4. Понятия не смешиваются

Онтология продукта описана в [docs/concept.md](docs/concept.md) и в коде держится буквально:

```
Space     — где            Agent   — кто
Skill     — что умеет      Context — что знает
Mode      — как работаем   Rule    — что нельзя
Memory    — что усвоили
```

Участник отвечает на вопрос «кто», режим — «как мы сейчас работаем». Три вопроса про людей
в комнате живут в трёх разных местах и не смешиваются:

- **Кто вообще есть** — каталог: Настройки → Участники. Там заводят и удаляют.
- **Кто сейчас в этой комнате** — тумблеры за кнопкой состава под полем ввода. Это свойство
  комнаты (`off` в её состоянии), а не участника: в одной комнате он есть, в другой нет.
- **Кто отвечает без тега** — дежурные режима, `modes/<режим>.md`.

Когда новая настройка не находит себе места в этой сетке — почти всегда неправильно назван
не файл, а сама настройка.

Человек — такой же участник: то же имя, та же аватарка из той же палитры, та же разметка
реплики. Отдельного «You» вместо имени и отдельной ветки в коде для него нет — как только
такая ветка заводится, за ней тянется второй набор правил, который никто не поддерживает.

## 5. Тексты интерфейса

Оболочка говорит на двух языках, и оба лежат одним словарём в `web/src/lib/i18n.tsx`: русская
и английская строки стоят рядом, поэтому не разъезжаются по смыслу. Литерала в JSX быть
не должно. Данные пространства — ники, роли, режимы — не переводятся: их завёл человек.

Тон — для взрослого человека.

- **Говорим, что произойдёт**, а не что система думает о себе: «Пауза. Начатые ответы
  допишутся», а не «Стоп».
- **Без канцелярита и без «Упс!».** Ошибка — это факт: «сервер вернул 500».
- **Всё длиннее трёх слов — через `typo()`**: предлоги и числа не должны висеть в конце строки.
- **Плейсхолдер — пример, а не инструкция:** «Собрать к пятнице спецификацию мегаменю»,
  а не «Введите цель».
- **Подпись не объясняет очевидное.** Полю «Имя» не нужна строка «как вас зовут». Описание
  уместно там, где без него выберут не то: уровень доступа, короткий режим.

## 6. Комментарии объясняют «почему»

Комментарий, пересказывающий код, — шум. Комментарий, объясняющий решение, — единственное
место, где это решение сохраняется.

```js
// Порядок участников сохраняем: он виден в шапке.
for (const [k, v] of Object.entries(s.agents)) agents[k === name ? next : k] = v
```

Язык комментариев — русский, как и весь разговор вокруг проекта. Идентификаторы — английские.

## 7. Проверка перед коммитом

```bash
npm test                     # движок на заглушках, токены не тратит
npm run dev                  # сервер и пересборка клиента на каждую правку
cd web && npm run build      # разовая сборка, тип-чек входит в неё
```

Участник правит файлы, но команд не запускает: при `npm run dev` его правка в интерфейсе
появляется сама, просить человека собрать не нужно.

Меняешь то, кого и когда зовут, — пишешь тест в `test/engine.test.mjs`. Оркестрацию глазами
не проверить: сбой там выглядит как участник, который «сам решил промолчать».

Меняешь сборку командной строки движка или разбор его ответа — тест в `test/cli.test.mjs`.
Эта граница ломается молча: чужой CLI меняет вывод, и комната просто замолкает.

На пуш в `main` то же самое гоняет CI (`.github/workflows/check.yml`).

Сломанная сборка в `main` дороже любой скорости. Правку интерфейса проверяем в браузере:
открыть экран, снять скриншот, сравнить с тем, что просили. Код, который компилируется,
не доказывает ничего — половина правок этого проекта выглядела в браузере иначе, чем в голове.

## 8. Git

- Ветка `main`, коммиты по-русски, повелительное наклонение: «убрать рамку у обращений».
- Одна мысль — один коммит.
- `/public/` и `rooms/` не коммитим: это сборка и данные машины. Слэш в начале обязателен,
  иначе правило ловит и `web/public/`, а это исходники.
- `git add <файлы>`, а не `-A`: над репозиторием работают несколько сессий сразу, и `-A`
  уносит в коммит чужую правку на середине.

## Грабли

Каждая уже стоила сломанного экрана или потерянной реплики.

- **Лента открыта наружу.** Сервер слушает localhost, но браузер ходит на localhost с любой
  страницы, а реплика здесь — команда агенту с доступом к файлам. Поэтому у не-GET проверяется
  `Origin`, у всех запросов — `Host`, а полю `from` верят, только если такой участник есть
  в составе. Новый POST наследует эти проверки — они стоят до разбора маршрута.
- **Состав команды.** Настройки шлют ростер целиком и обязаны ставить `replaceTeam: true`,
  иначе сервер домешивает прежний состав и переименование оставляет дубль. По той же причине
  `loadConfig` не мешает `DEFAULTS.agents` с диском: убранный участник не должен воскресать.
- **Кириллица в регулярках.** Везде, где разбираются ники и имена файлов, диапазон `Ѐ-ӿ`
  обязателен. Без него имя комнаты превращается в подчёркивания, а обращение не распознаётся.
- **`total_cost_usd` из `claude -p` — не деньги,** а пересчёт по API-тарифу. Оба движка
  работают по подписке, поэтому в интерфейсе расход показан в токенах.
- **Флекс режет текст.** Половины знака лежат во флекс-строке; без `flex: none` они ужимаются
  под ширину якоря, и слова обрезаются.
- **Сервер держит состояние в памяти.** Правка в `lib/` или `server.js` видна только после
  перезапуска `npm run dev`; правка в `web/src/` — сразу.

## Карта репозитория

```
server.js               HTTP, SSE, REST — один файл, без фреймворка
lib/
  orchestrator.js       кого будить и когда; движок режимов
  agents.js             запуск claude -p и codex exec, уровни доступа
  modes.js              разбор modes/*.md
  roles.js              разбор roles/*.md
  prompt.js             сборка системного промпта участника
  mentions.js           разбор @обращений
  memory.js             память пространства (пока не подключена)
  store.js              лента комнаты, rooms/<комната>.jsonl
  state.js              режим, шаг, пауза, сессии — чтобы комната пережила перезапуск
  config.js             DEFAULTS и openspace.config.json
roles/                  по файлу на роль
modes/                  по файлу на режим, отложенные — в modes/архив/
web/src/                клиент: React + Vite + Tailwind 4 + shadcn/ui
web/public/             фавиконка и знаки — исходники, не сборка
test/                   движок и разбор файлов на заглушках, `npm test`
bin/                    dev, say, hire, duel — из терминала
docs/                   концепция, устройство, научная база групповой динамики
```

## Как добавить

**Роль** — файл `roles/<имя>.md`, формат в [roles/README.md](roles/README.md).
**Режим** — файл `modes/<имя>.md`, формат в [modes/README.md](modes/README.md), либо прямо
в интерфейсе: Настройки → Режимы. Редактор пишет тот же файл.
**Компонент** — `npx shadcn@latest add <имя>` в `web/`, потом использовать как есть.
